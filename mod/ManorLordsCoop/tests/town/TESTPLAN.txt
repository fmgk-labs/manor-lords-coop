TESTPLAN - town actions module (mod/ManorLordsCoop/Scripts/coop_town.lua)

None of these files has been run. They were written without a game and without a Lua interpreter; a home-made Lua 5.4
syntax checker (tokenizer + recursive-descent parser) accepts all of them, nothing more.

== Setup for every one-copy test ==
- Test copies only: start the game with -saveddirsuffix=Coop (README session 14) and load coop_test_1 by name.
- The probe helper library is prepended to every test (eng, p1, sc, nm, v3, un, out). Load coop.lua, then
  Coop.start("host", "host", {}) (host with no friends: nothing follows the host's speed, no enemy switch), then load
  coop_town.lua. Check the log line "coop town ... loaded".
- t05 to t07 leave the game paused (pauseGame); the placement tests (t02, t04, t08, t09) un-pause and set speed 0, the
  only state placements were proven in.
- Never save. The core stops the helper's autosave timer (A.helper()); the tests never spawn a pawn themselves.
- Staged tests keep their state in _G.__tt; to abort one, run  _G.__tt = nil; Coop.town.test.uncap()  in the console.
- After any crash or a world reload: reload coop_test_1, start again from t00.

== Then two copies (host + one friend, both from coop_test_1, both with the separate save folder) ==
14  Real clicks on the FRIEND, one at a time: a cost-free building, a costed building (52), a road, a field, pause
    construction, priority, a production limit, a trade rule, family plus and minus, maintenance slider.
    Pass: the host's log shows "TOWN APPLIED <ACT> <friend>:<n>" for each and the same object on the host (type + position);
    the friend's log shows no "refused"; the host's link file shows the forwarded line; the friend never sends a second line
    for the same action (its own action comes back from the host and is ignored).
15  The same clicks on the HOST. Pass: the friend's log shows APPLIED for each; the host's link file has no line caused by a
    replay on the friend (friends never send replays: check the friend's link file has only its own lines).
16  Echo, delayed: on the friend, place a building, then within 1 s set its priority. Pass: two lines from the friend, the
    host applies BUILD then PRIO in that order (PRIO waits for the building: "retry"), no line from either side for the
    replays.
17  Referee: lower the host lord's silver below the cost of type 52 (console), place type 52 on the friend. Pass: the host
    log "FAILED BUILD ... cannot afford", the friend log "the host refused our action ... reload". (The friend's copy now
    has the building and the host not: that is the expected divergence; reload to repair.)
18  Switch an action off on the host only (Coop.town.enable("SLEEP", false)) and pause construction on the friend.
    Pass: host NAK "switched off here", the friend logs "refused". Switch it on again.
19  Static actions, one at a time on BOTH copies (Coop.town.enable(name, true) on each), in this order after their one-copy
    test passed: MOVE, DEMOLISH, ROADDEL, CPAUSE, RECIPE_ON/OFF, PROTECT, FERTILIZE, TAX, UPGRADE, EXT, ARTISAN, PASTURE,
    HOUSE (last). Pass for each: the action done by real click on the friend appears on the host and on a second friend
    (if any) with the same result; the drift fingerprint (world-state lane) shows no new difference.
20  A friend places a cost-free building while the HOST is paused (pauseGame). Pass: the host replays it after it is
    un-paused at the latest (its timeouts do not run while paused), no "timed out" in the host log, no crash.
21  A join or repair (Coop.join) while actions are being clicked. Pass: during the hold the module logs "dropped a T line
    during a join/repair hold" or nothing, after the reload "TOWN world reset", no errors, and the next click relays again.
